## 01. VA에서 추론형 VLA로
{: #resource-01 }

### 자율주행에서 파운데이션 모델을 쓰는 이유

발표는 2005년 DARPA 대회에서 차량이 환경을 파악하고 다음 행동을 고르는 데 어려움을 겪었던 모습으로 시작한다. 오늘날의 과제로는 일상 주행에서 드물게 나타나는 공사, 예상과 다른 교통 참여자의 움직임, 탑승자의 요청을 해석하는 일을 제시한다. 하나의 사례를 직접 수집하고 규칙으로 옮기는 데 비용이 들기 때문에, 대규모 영상·언어로 사전학습한 표현을 주행 과제에 재사용하는 접근을 소개한다.

### VA → VLA → 추론형 VLA

- **VA(Vision–Action)**에서는 영상으로 행동을 학습하고, 다음 영상을 예측하는 작업을 보조 목표로 붙인다. 현재 장면이 어떻게 변할지를 예측하도록 하면 차량·보행자의 움직임이나 도로 구조처럼 주행 판단에도 필요한 정보를 학습할 수 있다.
- **VLA(Vision–Language–Action)**는 시각·언어 사전학습을 거친 모델을 주행 모델의 기반으로 사용한다. 발표가 제시한 동일 구조 비교에서는 사전학습을 활용했을 때 궤적 오차가 낮아지고 학습이 더 빨리 수렴했다.
- **추론형 VLA**는 미래 궤적과 함께, 관측한 단서가 행동에 어떤 영향을 주었는지 언어로 나타낸다. 예를 들어 공사 콘이 자기 차로의 폭을 좁힌다면, 콘을 발견하는 단계에서 옆 차로와의 간격을 고려하고 감속하는 단계로 이어진다.

### 모델과 개발 도구의 관계

Cosmos Reason은 물리 장면 해석을, Embed는 데이터 검색을 돕는다. Predict와 Transfer는 미래 장면의 생성이나 관측 조건의 변형에 쓰인다. 발표에서 Alpamayo의 공개 플랫폼은 **추론형 모델, 실제 주행 데이터셋, 폐루프 시뮬레이터**를 묶어 소개한다. 차량에서는 추론 지연과 연산량이 제한되므로, 큰 모델로 데이터에 라벨을 붙이거나 정책을 평가하고 그 능력을 차량용 모델에 옮기는 방법도 함께 다룬다. 차량이 탑승자와 대화하는 시연은 지시를 입력받고 판단 근거를 출력할 수 있다는 사례이며, 어떤 요청을 허용하는지는 안전 제약과 함께 설계하는 부분이다.

## 02. 공사 구간의 카메라 입력과 궤적 출력
{: #resource-02 }

### 공사 구간 예제의 입력과 출력

기술 글의 첫 실습은 공개 모델 가중치와 노트북을 사용해 **전방의 네 카메라에서 얻은 여러 시점의 영상**과 자차의 과거 움직임을 Alpamayo 1에 입력한다. 영상의 변화는 콘과 작업 차량의 상대 위치를 파악하는 데 쓰이고, 자차 운동 기록은 같은 영상 변화가 자차의 진행·회전과 어떻게 연결되는지 해석할 기준이 된다. 모델은 주행 판단의 근거와 미래 궤적을 반환한다. 글에서는 이 궤적을 실제 기록과 겹쳐 공사 구간에서 어떤 경로를 골랐는지 확인한다.

### 데이터와 시뮬레이션을 준비하는 과정

Physical AI AV Dataset에는 센서 영상과 차량 움직임 외에도 센서별 시간과 캘리브레이션 정보가 담겨 있다. 기술 글에 제시된 공개 데이터 스냅숏은 25개국, 2,500곳 이상의 도시에서 수집된 1,727시간을 다룬다. **일반 주행 클립**은 기록에 대한 개루프 추론에, **NuRec으로 복원한 장면**은 다른 경로나 시점의 관측을 다시 렌더링하는 폐루프 실험에 사용한다.

AlpaSim의 런타임은 차량 운동, 센서 렌더링, 교통 참여자, 주행 정책 서비스를 연결한다. 글의 사용자 정책 연결 절차는 시뮬레이터가 관측을 전달하고 정책이 행동을 반환하도록 **gRPC 인터페이스**를 맞춘 뒤, 설정에서 쓸 정책과 장면을 지정하는 방식이다. 여러 롤아웃에서 각 서비스의 작업을 겹쳐 실행할 수 있어 장면 수를 늘릴 때 필요한 자원을 분산한다.

### 결과를 읽는 방법

개루프 궤적 그림은 **같은 관측에서 예측이 기록과 얼마나 다른지** 보여준다. 폐루프에서는 예측을 실행한 결과가 다음 영상이 되므로 처음의 오차가 커지는지, 정책이 회복하는지도 보인다. 글의 시뮬레이션 출력에는 카메라, 상공에서 본 객체·지도, 시간별 지표가 함께 표시된다. 예를 들어 최소 객체 거리와 차로 중앙에서의 편차를 함께 보면, 차로 중앙을 벗어난 움직임이 장애물을 피하는 과정인지 불안정한 주행인지 영상으로 다시 확인할 수 있다.

## 03. 판단 근거를 주행 행동과 맞추는 학습
{: #resource-03 }

### 장면 설명과 행동의 원인을 구분하기

Alpamayo 1은 카메라 영상과 자차의 움직임을 받아 언어로 된 주행 근거와 미래의 연속 궤적을 생성하는 10B급 모델이다. **Chain of Causation(CoC)**은 장면을 일반적으로 묘사하는 작업보다 좁다. 예를 들어 도로에 차량과 사람이 있다는 사실을 나열하는 대신, 차로를 가로막은 작업 차량 때문에 감속하고 왼쪽으로 여유를 두었다는 식으로 **관련 단서와 결정의 관계**를 붙인다. 공개 논문에서는 자동 라벨링과 사람의 검토를 결합해 이런 예시를 만드는 방법을 설명한다.

### 궤적을 만드는 방식과 후학습

모델은 연속적인 위치와 자세를 언어 토큰처럼 처리할 수 있는 이산 표현을 학습에 활용하고, 추론에서는 **확산 계열 Action Expert**로 물리적으로 실행 가능한 연속 궤적을 생성한다. 언어 모델이 만들어 내는 설명과 제어에 전달할 연속 궤적은 필요한 정밀도가 다르다. 예를 들어 ‘왼쪽으로 조금 이동’이라는 의미가 같아도, 차선과 장애물 사이를 지날 때 요구되는 이동량과 진행 속도는 장면마다 달라진다.

지도 미세조정(SFT)은 관측과 설명의 예를 학습시키고, 강화학습은 생성한 설명이 상황에 맞고 행동과 일치하는지에 대한 점수를 반영한다. 설명은 왼쪽 회피라고 했는데 궤적은 오른쪽으로 향하는 경우가 **추론과 행동의 불일치**다. 문장만 매끄럽게 생성하거나 기록 궤적만 비슷하게 따라가는 평가에서는 이런 오류가 가려질 수 있다.

### 발표 결과를 해석하는 범위

Alpamayo-R1 논문은 해당 벤치마크에서 궤적만 학습한 기준 모델과 비교해 어려운 장면의 계획 정확도가 최대 12% 개선됐고, 폐루프 시뮬레이션에서 근접 위험 사건의 비율이 35% 줄었다고 보고한다. 이 두 수치는 각각 다른 평가의 결과다. 근접 위험 감소는 논문이 사용한 장면과 판정 기준 안에서 읽어야 하며, 다른 운행 조건의 안전성은 해당 조건의 시험으로 확인한다.

## 04. Alpamayo 2 Super의 확장된 입력과 출력
{: #resource-04 }

### 주변 영상과 경로 조건을 함께 받는 모델

발표가 소개한 Alpamayo 2 Super는 카메라 여러 대의 주변 영상과 과거 자차 운동, 내비게이션 지시를 함께 활용한다. 자기 차로에서만 보이는 정보로 판단하기 어려운 합류나 차로 변경의 경우, 주변 카메라가 빈 공간이나 옆에서 접근하는 차량을 확인할 단서를 제공한다. 내비게이션은 어디로 갈지 조건을 주고, 실제로 언제 이동할 수 있는지는 영상과 차량 상태를 함께 봐야 결정할 수 있다.

### 출력별 쓰임과 공개 모델 구성

| 출력 | 의미 | 활용 예 |
| --- | --- | --- |
| 추론 근거 | 어떤 관측이 판단에 영향을 주었는지 설명 | 위험 장면에 학습용 근거 라벨 생성 |
| 메타 행동 | 감속·차로 유지·변경처럼 높은 수준의 행동 표현 | 정책의 의도를 빠르게 확인 |
| 미래 궤적 | 차량이 앞으로 지나갈 위치와 움직임을 연속적으로 표현 | 주행 경로 비교와 폐루프 실행 |

발표의 32B는 공개된 최종 모델에서 **Cosmos 3 Super Reasoner**에 해당한다. 기술 글이 명시한 전체 구성은 이 부분에 **2B 확산 기반 Action Expert**를 더한 **34B**다. 큰 모델은 궤적을 직접 생성하는 정책 외에도 라벨링과 평가에 사용할 수 있다. 평가 모델인 AlpaJudge처럼 설명의 인과적 품질을 채점하는 도구는 근거 문장이 얼마나 적절한지를 보고, 시뮬레이터는 해당 궤적을 실행했을 때 차량이 어떤 결과를 만드는지 본다.

### 평가를 두 가지로 나누는 이유

기록된 궤적에 가까운지 측정하는 개루프와, 충돌·근접·진행 같은 주행 결과를 보는 폐루프는 서로 다른 정보를 준다. 공개 기술 글은 실제 기록 기반 장면과 AlpaSim 장면을 각각 평가에 사용한다. 같은 상황의 안전한 경로가 여러 개일 수 있으므로, 기준 궤적과 거리가 벌어졌을 때 안전한 대안이었는지 실제 주행 결과도 함께 확인해야 한다.

## 05. 센서 기록을 학습 가능한 클립으로
{: #resource-05 }

### 공개 데이터가 담는 것

발표 당시 공개한 주행 기록은 **20초 단위 약 30만 클립, 1,700시간 이상**이다. 여러 지역, 시간대, 도로와 교통 상황을 포함한다. 한 클립에는 주변 카메라 영상, LiDAR, 레이더, 자차 운동과 같은 여러 유형의 관측이 연결된다. 센서에 따라 프레임 시각과 좌표계가 다르므로, 카메라의 **내참수**로 3D 정보가 영상 어디에 투영되는지 계산하고, **외참수**로 센서 좌표를 차량 좌표로 바꾼다. 시각 정보는 서로 다른 센서가 어느 순간을 기록했는지 맞추는 데 쓰인다.

### 필요한 클립과 특징만 받는 구조

발표는 같은 클립에 고유 식별자를 부여하고, 영상·라벨·운동 정보 등은 유형별로 나눠 보관하는 구조를 설명한다. 같은 클립 ID로 해당 영상과 운동·라벨 파일을 다시 연결할 수 있다. 전체 분량이 크기 때문에, 먼저 메타데이터나 검색 도구로 공사·합류처럼 필요한 클립을 고른 뒤 쓸 센서만 선택한다. 예를 들어 발표의 Alpamayo 1.x 사례에는 전방 카메라 네 대와 자차 운동이 필요하지만, LiDAR 기반 검출을 연구할 때는 다른 입력과 보정 정보가 필요하다.

### 원시 관측, 주행 라벨, 추론 라벨

원시 관측은 센서가 기록한 결과이며, 객체 박스나 지도 정보 등은 관측을 학습·평가에 활용하기 위한 주석이다. 추론 라벨은 자차가 감속하거나 회피한 이유를 장면 단서에 연결해 표현한다. 세션은 사람이 검토한 추론 라벨과 확장 가능한 자동 라벨링을 소개한다. 전체 클립 수가 커도 특정 가림, 도로공사, 상호작용의 사례는 드물 수 있다. 따라서 **지역·센서 범위와 과제별 사례의 분포**를 각각 살펴야 데이터가 무엇을 뒷받침하는지 알 수 있다.

## 06. 내비게이션 조건과 상황 질의응답
{: #resource-06 }

### 한 모델에서 세 출력을 맞추는 이유

발표의 주행 모델은 여러 카메라에서 여러 시점에 얻은 영상과 자차 운동을 보고, 필요하면 내비게이션이나 사용자 지시를 입력으로 받는다. 출력은 **추론 근거, 메타 행동, 미래 궤적**이다. 예를 들어 차로에 작업 차량이 있으면 ‘오른쪽이 막혀 있다’는 관측, ‘간격을 두고 지나간다’는 행동, 실제로 어디까지 비켜 갈지 나타내는 궤적을 비교할 수 있다. 앞선 관측과 뒤의 행동을 따로 볼 수 있어서, 문제가 장면 이해인지 행동 선택인지 추적할 단서가 생긴다.

### 지도 미세조정과 강화학습의 역할

기본 주행을 배운 뒤 SFT로 자동 라벨링한 추론 예시를 학습하고, 강화학습에서는 모델이 직접 생성한 후보에 점수를 준다. Alpamayo 1.5 발표는 평가 신호를 추론 품질, 주행, 다른 시각·언어 과제로 넓히는 방향을 설명한다. 시각·언어를 맡는 **VLM**과 연속 궤적을 내는 **Action Expert**가 분리돼 있으므로, 발표는 두 부분에 대한 강화학습 단계를 구분한다. 자연스러운 설명이 곧바로 적절한 궤적을 보장하지 않기 때문에, 두 출력이 연결되는 부분도 평가 대상이다.

### 같은 장면에서 경로 지시만 바꾸는 시연

시연에서는 같은 영상에 일정 거리 뒤 좌회전과 우회전을 각각 입력했을 때 궤적이 어떻게 달라지는지 본다. 지시가 없는 경우 교차로에서 여러 후보가 나올 수 있고, 지시를 주면 그 방향에 해당하는 후보가 더 뚜렷해진다. 발표는 **classifier-free guidance**로 조건을 줬을 때와 주지 않았을 때의 생성 방향 차이를 이용해 지시의 영향을 조절하는 예도 보여준다. 별도의 시각 질의응답(VQA)은 보행자나 장애물의 위치 등 장면 이해를 문장으로 확인하는 데 쓰인다. 경로 지시 준수, 장면 질의응답, 실행 가능한 궤적은 각기 확인할 항목이다.

## 07. 안전 목표를 데이터 검색 조건으로 바꾸기
{: #resource-07 }

### 안전 목표에서 출발하는 데이터 선별

이 세션은 주행 정책, 평가기, 차량에서 정책을 감시하는 구성요소를 개선할 때 어떤 데이터를 모아야 하는지 다룬다. 예를 들어 ‘합류 중 앞 차량이 가까이 끼어드는 상황에서 간격을 확보한다’는 목표가 있다면, 먼저 차량 간 거리·접근 속도나 차로 변경 관련 메타데이터를 활용해 후보를 좁힐 수 있다. 장면을 문장으로 표현한 검색은 정형 태그로 표현하기 어려운 사례를 찾는 데 쓰인다. 후보가 목표에 맞는지는 영상과 센서 기록을 함께 검토한다.

### 실패를 학습과 검증으로 되돌리는 흐름

1. **선별** — 실제 기록에서 위험과 관련된 장면을 검색하고, 주행 정책이 어려워하는 상황을 묶는다.
2. **분석과 라벨링** — 무엇이 위험했는지, 정책이 언제 위험을 인식했는지, 어떤 대응을 했는지 비교한다. 추론 문장의 근거가 영상에 실제로 있었는지도 본다.
3. **개선과 재시험** — 정책을 후학습하거나 감시 기준을 바꾼 뒤, 학습에 쓰지 않은 유사 장면을 포함해 다시 평가한다. 실패가 남으면 어떤 상황을 추가로 찾아야 하는지 정한다.

### 안전 감시와 반사실 비교

발표가 다루는 병렬 안전 구조에서는 주행 경로를 내는 정책과 별도로, 주변 위험이나 주행 결과를 확인하는 구성요소를 둔다. 예를 들어 정책이 끼어든 차량을 인식했다고 말하더라도, 실제 궤적이 충분한 거리를 확보했는지는 별도 기준으로 확인한다. 또 같은 상황에서 상대 차량의 행동이나 조건을 하나 바꾸는 **반사실 비교**는 정책이 어떤 단서에 민감한지 보는 방법이다. 공개 데이터와 자동 라벨은 후보를 찾고 비교를 늘리는 데 유용하며, 평가에는 라벨 품질과 검증 기준이 함께 필요하다.

## 08. AlpaSim과 AlpaGym이 공유하는 폐루프
{: #resource-08 }

### 개루프의 오차와 폐루프의 누적 오차

기록 영상으로 추론할 때는 첫 예측이 빗나가도 다음 입력으로 원래 기록의 올바른 시점이 들어온다. 폐루프에서는 모델이 움직인 위치와 방향에 맞춰 다음 관측을 다시 만든다. 차량이 차로 중심을 조금 벗어나면 다음 관측에서 차선의 위치가 달라지고, 그 차이에 맞춰 복구하지 못하면 편차가 커질 수 있다. 발표는 개루프 지표가 좋은 정책도 폐루프에서 다른 순위를 보일 수 있다는 점을 설명한다.

### AlpaSim에서 한 번의 주행이 실행되는 방법

중앙 런타임이 각 실행을 조정하고, **정책, 렌더러, 교통 참여자, 제어기, 차량 물리** 같은 서비스를 gRPC로 연결한다. 정책이 새로운 궤적을 보내면 제어·물리가 자차 상태를 갱신하고, 렌더러는 해당 위치의 카메라 관측을 만들어 정책에 돌려준다. 이 과정을 반복한 실행이 **롤아웃**이다. 여러 롤아웃을 겹쳐 실행하면 한 정책이 렌더링을 기다리는 동안 다른 실행을 처리할 수 있다. 세션은 특정 서비스에 대기가 집중되는지 확인하고, 해당 구성의 인스턴스나 자원을 조정하는 방법을 설명한다.

### 평가 장면과 학습으로의 연결

복원된 실제 장면은 카메라를 통한 평가에 유용하고, 교통 참여자가 달라지는 시나리오는 반응과 복구 능력을 더 다양하게 시험할 수 있다. 발표는 원래 주행 경로에서 멀어진 시점의 영상 품질, 교통 참여자 모델의 다양성, 시뮬레이션과 실세계의 차이도 다룬다. 특히 충돌률을 읽을 때는 주변 차량의 재현 방식이 만든 오탐 가능성도 살펴야 한다.

AlpaGym은 이 롤아웃을 수집하고 보상을 계산해 학습기로 보낸다. 정책이 갱신되면 다음 롤아웃에 새 행동이 반영된다. 실제 영상 수준의 관측을 계속 만들려면 렌더링과 모델 추론이 모두 필요하므로, 학습 예제의 성패와 별도로 처리량과 비용이 중요한 설계 조건이 된다.

## 09. 강화학습 보상을 설계하고 결과를 검증하기
{: #resource-09 }

### 학습을 시작하기 전에 정하는 것

이 튜토리얼은 Alpamayo 1.5의 기존 가중치를 시작점으로 잡고, 폐루프 주행 결과를 이용해 모델을 추가로 학습한다. 설정에서 **초기 체크포인트, AlpaSim 장면 집합, 동시에 실행할 롤아웃 수, 보상 함수, Cosmos-RL 학습 옵션**을 정한다. NuRec 장면은 시뮬레이션에서 다시 렌더링할 수 있는 자산으로 준비한다. 예제에서는 모델과 시뮬레이션이 자원을 많이 쓰므로 장면 저장 공간과 GPU 메모리도 별도로 고려한다.

### 롤아웃, 보상, 정책 갱신

롤아웃 작업자는 현재 정책을 사용해 AlpaSim에서 차량을 움직이고, 에피소드가 끝나면 주행 결과와 지표를 돌려준다. AlpaGym은 이 정보를 보상으로 계산하고, Cosmos-RL의 학습 과정에 연결한다. 진행을 보상하고 충돌·도로 이탈에 벌점을 주는 방식이 출발점이다. 차로 중앙 유지, 안락한 가감속, 기준 궤적과의 거리 같은 항목도 목적에 따라 넣을 수 있다. 진행만 크게 보상하면 무리하게 달릴 수 있고, 충돌 벌점만 크게 주면 계속 정차하는 행동이 유리해질 수 있으므로 **실제로 원하는 행동과 보상 항목이 맞는지** 점검한다.

### 체크포인트를 검증하는 순서

학습 중에는 보상 평균과 분산, 충돌·이탈률, 주행 속도, 롤아웃 처리량과 같은 신호를 확인한다. 튜토리얼에서는 학습 결과를 AlpaSim 정책이 읽을 수 있는 추론 형식으로 변환한 뒤 대표 장면을 실행해 연결을 검증한다. 다음으로 학습에 사용하지 않은 장면에서 초기 정책과 후학습 정책을 같은 조건에 두고 비교한다. 총점이 높아졌다면 기록된 롤아웃과 세부 지표로, 실제 충돌이 줄었는지 아니면 지나치게 느리게 주행해 벌점을 피했는지를 구분할 수 있다.

## 10. 연구 모델을 차량에서 쓸 때 바뀌는 조건
{: #resource-10 }

### 관측 시점과 추론 라벨의 경계

발표는 연구 모델을 차량에 넣기 위해 **데이터의 인과적 일관성, 설명과 행동의 정합성, 차량의 시간 예산**을 함께 다룬다. 사람의 행동을 설명하는 라벨을 만들 때 기록 전체를 볼 수 있으면, 나중에 신호가 바뀌거나 옆 차가 움직인 사실을 과거 판단의 근거로 쓰기 쉽다. 이를 **미래 정보 누출**이라고 한다. 학습의 정답은 차량이 판단할 때 볼 수 있었던 단서에 근거해야 한다. 미래 기록은 실제 결과를 평가하는 데 쓸 수 있지만, 판단 시점의 입력과는 구분한다.

### 설명과 궤적을 맞추고 필요할 때 다시 추론하기

추론 근거, 메타 행동, 연속 궤적이 함께 나오는 모델에서는 세 출력이 같은 행동을 가리키는지 검사할 수 있다. 예컨대 설명과 메타 행동은 양보인데 실제 궤적은 회전교차로 쪽으로 가속한다면, 각 출력이 개별적으로 그럴듯해도 서로 어긋난다. 발표는 여러 후보를 생각해 보고, 위험한 결과가 예상되면 처음 궤적을 수정하는 **반사실적 추론** 사례도 보여준다. 상대 차량의 의도가 완전히 관측되지 않는 상황에서 가능한 결과를 비교한다는 뜻이다.

### 차량에서 시간 안에 끝내는 방법

클라우드 연구 모델의 능력을 차량용 모델에 증류하고, 상황에 따라 추론 길이를 조절할 수 있다. 발표의 실시간 예에서는 전체 단계가 약 **100 ms의 목표 시간** 안에 들어오는지 검토한다. 언어 토큰을 한 개씩 생성하는 비용을 줄이는 예로 **추측 디코딩(speculative decoding)**을 소개한다. 빠른 방식으로 토큰 후보를 만들고 본 모델이 후보를 검증하는 방법이다. 시간은 언어 생성만 따로 재기보다 카메라 처리, 언어 추론, 궤적 생성까지 하나의 주행 주기로 보는 것이 발표의 핵심이다.

## 11. 공개 생태계에서 달라지는 연구 단위
{: #resource-11 }

### 업체가 조합하는 공개 개발 요소

세션은 차량의 센서·컴퓨팅을 정의하는 **Hyperion 레퍼런스 아키텍처**와, 개발 단계에서 사용하는 공개 모델·데이터·시뮬레이션 도구의 역할을 나눈다. OEM은 기존 센서와 소프트웨어에 맞게 필요한 구성요소를 조합할 수 있고, 연구자는 같은 장면에서 정책만 바꾸거나 같은 정책으로 시뮬레이션 장면을 바꿔 결과 차이를 볼 수 있다. 공개된 가중치, 코드, 데이터에는 각각의 이용 조건이 적용된다.

### 재구성, 물체 재사용, 생성형 렌더링

| 도구 | 해결하려는 문제 | 입력과 출력 |
| --- | --- | --- |
| InstantNuRec | 관측 장면에서 재구성을 빠르게 시작 | 입력 영상에서 Gaussian 장면 표현을 생성 |
| Asset Harvester | 관측된 객체를 다른 시험에 다시 사용 | 여러 이미지에서 차량 같은 3D 자산을 분리·재구성 |
| OmniDreams | 기록에 없던 관측 조건으로 시험 범위를 넓힘 | 시뮬레이션 상태와 조건에 맞는 관측을 순차적으로 생성 |

복원 장면은 이미 관측한 환경을 재현하기 좋고, 생성형 렌더러는 직접 수집하기 어려운 날씨나 상황으로 범위를 넓힌다. 예를 들어 차량을 새로 배치하는 일과, 그 차량이 여러 카메라에서 같은 위치와 움직임으로 보이도록 영상을 만드는 일은 별도 문제다.

### 규모를 늘릴 때의 고려사항

장면을 재구성하는 비용, 롤아웃 한 번에 걸리는 시간, 생성 영상의 일관성은 정책을 평가하고 다시 학습할 수 있는 장면 수에 영향을 준다. 세션이 생성 추론을 가속하는 FlashDreams도 함께 소개한 이유다. 생태계의 구성요소를 따로 개선할 수 있으면, 평가 성능이 달라졌을 때 정책의 변화인지 관측을 만드는 방식의 변화인지 구분하기 쉽다.
